# Evaluation integrity

**Read first:** `../data_and_evaluation.md` ("Task-appropriate evidence", "Splits, principals and sealed
access", "Evaluation contract", "Statistical treatment", "Notebooks and HTML evidence");
`../reference_workload.md`; D01, D09, D10, D12; scenarios A01, A02, A13, A14, A29, A36.

## Analysis (no model)

Freeze question, population, grain, joins, denominators and material claims. Acceptance: hard
schema/key/lineage checks pass **and** material aggregates match an independent recomputation (a separately
written query) within the declared rounding. Missing coverage or unreviewed assumptions →
INSUFFICIENT_EVIDENCE; a violated check → FAIL. EDA is exploratory: no causal claims, sampled profiles labelled.
Zero trials.

## Predictive

1. **Split first,** before any learned step. Group by entity or scenario family, or by time, according to
   what the estimate should generalise to. Freeze a `SplitManifest` with explicit membership and overlap
   checks. Data the user already explored cannot be a sealed final set.
2. **Train-only transforms:** every imputer, scaler, vectoriser, encoder and selector lives inside the
   sklearn `Pipeline` and fits on training folds only. The fitted pipeline is what ships.
3. **Baselines first:** a deterministic or conventional baseline (majority class, training median, quoted
   value, keyword rules) evaluated on the same protocol.
4. **Bounded search** (D01): ≤ 12 configurations, one at a time, from a declared finite domain. Record every
   configuration, including failed ones, in the trial ledger.
5. **Sealed evaluation:** a separate evaluator principal holds final inputs, labels and the oracle. The
   candidate runs inference-only in the sandbox on streamed inputs, with no labels and no directory listing.
   One evaluation per authorisation (D09); the optimiser gets aggregates only (D10).
6. **Outcome:** PASS, FAIL or INSUFFICIENT_EVIDENCE against a frozen `EvaluationContract`. Thresholds are an
   owner checkpoint: present the baseline numbers and options, then wait. No threshold is tuned after seeing
   final results. An empty feasible set selects no winner.

## User constraints (R17)

Identifiers are strings, excluded from predictors, never returned by default. "Minimal features" needs a
counting unit and a hard cap or a soft objective. An output transform (round to increment, declared ties) is
part of the evaluated pipeline: evaluate the released rounded output and keep raw diagnostics restricted.
Rounding is precision, not anonymity. A changed feature rule needs a refit; a changed postprocessor needs a
new evaluation and release.

## Uncertainty

Bootstrap by group, 2,000 resamples by default. Slices under the declared minimum are INSUFFICIENT_EVIDENCE,
however good the point estimate. Metrics in business units (MAE in hours). Classical fit is "actual training"
only if learned parameters exist (A14).

## Reports and notebooks

Generated by package code from committed run artifacts and the signed `EvaluationReport` JSON. Self-contained
HTML, no scripts or remote assets, all untrusted text escaped. Missing values say "not measured". Notebooks
call the same library code as the job and pass a fresh-kernel replay. No raw sensitive rows by default.
The local build cannot give adversarially independent sealing: say `operator_controlled_local`.

## Tests that must exist

Optimiser credentials denied every route to final data (A01); a sentinel feature placed only in the final
partition never appears in fitted vocabulary or statistics (A02); tiny or missing slice yields
INSUFFICIENT_EVIDENCE with no winner (A13); ID exclusion, grouped split, feature cap and rounding ties
124→120, 125→130, −125→−130 (A29); a "sealed" cohort the assistant already explored is rejected (A36).
